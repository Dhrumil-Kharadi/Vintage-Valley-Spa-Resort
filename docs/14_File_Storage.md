# 14 — File Storage

## Overview

The application uses **local static file serving** for images and assets. There is no cloud storage (S3, GCS, etc.) or file upload API. All images are pre-placed in the filesystem and referenced by URL path.

---

## Static Asset Locations

### Frontend Static Files (`Frontend/public/`)

| Directory | Contents | Served At |
|-----------|----------|-----------|
| `Frontend/public/images/` | Room photos, resort images | `/images/*` |
| `Frontend/public/images/room/` | Room-specific photos | `/images/room/*` |

### Production Static Files

In production, the Vite build copies `public/` contents to `dist/`, which is then deployed to `/var/www/html/`:

```bash
cp -r dist/* /var/www/html/
```

Nginx serves these as static files at the root domain.

## Image References

### Room Images (Database)

Room images are stored as URL strings in the `RoomImage` table:

```prisma
model RoomImage {
  id        String @id @default(cuid())
  roomId    Int
  url       String    // e.g., "/images/deluxe-studio-suite-1.jpg"
  sortOrder Int @default(0)
  room      Room @relation(fields: [roomId], references: [id])
}
```

### Seed Data Images

| Room | Images |
|------|--------|
| Deluxe Studio Suite | `/images/deluxe-studio-suite-1.jpg`, `-2.jpg`, `-3.jpg` |
| Deluxe Edge View | `/images/deluxe-edge-view-1.jpg`, `/images/room/4.jpeg`, `/images/room/5.jpeg` |
| Lotus Family Suite | `/images/1.jpeg`, `/images/room/AB004957.JPG`, `/images/room/AB004912.JPG` |
| Presidential Suite | `/images/room/1.jpeg`, `/images/room/1000021300 (1).jpg`, `/images/room/1000021301 (1).jpg` |

### eZee Room Images

The `room_main_image` field from eZee API responses contains URLs hosted on eZee's CDN. These are passed through directly to the frontend.

## Image Management (Admin)

The Admin API allows updating room images:

```typescript
// adminRoomService.ts
await tx.roomImage.deleteMany({ where: { roomId } });
await tx.roomImage.createMany({
  data: images.map((url, idx) => ({ roomId, url, sortOrder: idx }))
});
```

- Images are replaced (delete all + create new) on each update
- URL strings are stored — no actual file upload
- Admin must place image files manually in the `public/images/` directory

## PDF Invoices

PDF files are generated **in-memory** and sent as email attachments. They are never stored on disk.

### Server-Side (Backend)
- Generated by `invoicePdf.ts` using jsPDF
- Used for email confirmation attachments
- Buffer returned directly from `generateBookingInvoicePdfBuffer(booking)`

### Client-Side (Frontend)
- Generated by `Frontend/src/lib/invoicePdf.ts` using jsPDF
- Used for "Download Invoice" button in Profile page
- Downloaded directly in browser via blob URL

## File Naming Conventions

| Pattern | Example |
|---------|---------|
| Room photos | `deluxe-studio-suite-1.jpg` (kebab-case) |
| Generic room photos | `/images/room/4.jpeg` (numbered) |
| Camera photos | `/images/room/AB004957.JPG` (original camera name) |
| Guest photos | `/images/room/1000021300 (1).jpg` (phone camera name) |

> **Note**: Some image filenames contain spaces and parentheses, which may cause issues in some environments. URL encoding handles this in HTTP but filesystem operations should be tested.

---

## No File Upload System

The current codebase does **not** include:
- File upload API endpoints
- Multer or similar upload middleware
- Cloud storage integration (AWS S3, Google Cloud Storage)
- Image optimization or resizing
- CDN configuration

All images must be manually placed on the server filesystem.
